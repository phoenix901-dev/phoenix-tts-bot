# Phoenix TTS Bot

Асинхронный Telegram-бот для конвертации текста и книг в естественную речь. 

## Философия. Зачем это нужно?
Проект создан на принципах **цифрового суверенитета и честного железа**. 
Отказ от платных корпоративных API (Yandex, Google Cloud, AWS) в пользу прямых запросов к нейронным сетям Microsoft Edge. Вся тяжелая работа по парсингу, нарезке текста и рендерингу аудиопотока выполняется на вашем сервере. Вы получаете полный контроль над процессом генерации контента без лимитов на символы и скрытых подписок. Приоритет отдан физике потока и стабильности при обработке больших массивов данных (книг).

## Техническая база
* **Ядро:** Python 3.10+, Aiogram 3.x (Async)
* **Синтез:** `edge-tts` (Нейронные голоса без квот)
* **Медиа-движок:** `FFmpeg` (Конкатенация чанков в MP3 и автоматическая прошивка ID3-тегов)
* **Парсинг:** `Pandoc`, `pdftotext` (Извлечение текста с сохранением семантики), встроенный regex-чистильщик текста
* **БД:** `SQLAlchemy` + `aiosqlite`
* **Очередь:** Глобальная асинхронная очередь `asyncio.Semaphore` (защита от DDoS и перегрузки CPU)

## Что нужно поставить (Установка)

1. **Системные зависимости** (для работы с аудио и документами):
```bash
sudo apt update && sudo apt install ffmpeg pandoc poppler-utils -y
```

2. **Зависимости Python** (находясь в папке с ботом):
```bash
pip install -r requirements.txt
```

3. **Инициализация:**

Секреты и настройки проекта лежат в `.env` рядом с кодом (файл в `.gitignore`,
в репозиторий не попадает). Переменные окружения, заданные снаружи, имеют
приоритет над файлом — старые установки со `EnvironmentFile` продолжают
работать.

```bash
cat > .env <<'EOF'
TELEGRAM_BOT_TOKEN="123456:AA..."
TTS_TMP_DIR="/root/telegram/bbot/tmp"
TTS_DB_PATH="tts_bot.db"
TTS_LOG_FILE="/var/log/tts-bot.log"
# Раздача готовых книг ссылкой (см. ниже)
PUBLIC_BOOKS_DIR="/var/www/books"
PUBLIC_BASE_URL="https://book.2aim.ru"
BOOK_TTL_DAYS="7"
EOF
chmod 600 .env
```
*Убедитесь, что у скрипта есть права на запись в `TTS_TMP_DIR`.*

4. **Запуск:**
```bash
python main.py
```

## Как пользоваться

После запуска бота и отправки команды `/start`:

1. **Мгновенный TTS (Голосовые сообщения):**
   Отправьте любой текстовый фрагмент. Бот асинхронно сгенерирует аудио и вернет его в формате нативного голосового сообщения Telegram (Opus, Voice).

2. **Создание аудиокниг из файлов:**
   Отправьте боту документ. Поддерживаемые форматы: `PDF`, `DOCX`, `FB2`, `EPUB`, `TXT`.
   * Бот самостоятельно извлечет текст с помощью `pandoc`/`pdftotext`.
   * Разобьет его на тома по ~75 000 символов (около 1.5 часа речи). Размер подобран
     под лимит Telegram Bot API в 50 МБ: edge-tts отдаёт MP3 48 кбит/с, и 75 000
     символов дают ~32 МБ.
   * Отрендерит аудио и склеит фрагменты через FFmpeg.
   * Готовая книга уходит **ссылкой на наш сервер** (см. «Раздача книг по ссылке»):
     Телеграм не пускает вложения больше 50 МБ, а книга целиком бывает и на 300 МБ.
     Если часть одна и она меньше 45 МБ, бот дополнительно приложит её файлом.

### Раздача книг по ссылке

Готовые тома складываются в общий каталог (`PUBLIC_BOOKS_DIR`, по умолчанию
`/var/www/books`) в подкаталог со случайным токеном и получают короткий адрес
вида `https://book.2aim.ru/AbCdEf123/`. Там же лежит страница со списком частей
и архив всех частей одним файлом.

* Ссылку нельзя угадать: имя каталога — случайный токен, а листинг каталогов
  запрещён, работает только страница книги и прямые ссылки на файлы.
* Файлы старше `BOOK_TTL_DAYS` (по умолчанию 7) дней удаляются ежедневным
  кроном `scripts/cleanup_books.sh`.
* Раздача идёт через прокси-фасад: Apache на боевом сервере слушает отдельный
  порт 8080 и пускает на него только прокси (все остальные получают 403),
  а сертификат и HTTPS держит Caddy на прокси. Конфиг Apache —
  `deploy/apache-books.conf`, блок Caddy — `deploy/caddy-book.2aim.ru.conf`.
* Докачка поддерживается: сервер отвечает на Range-запросы.

Если публикация не удалась (нет каталога, кончилось место), бот честно
откатывается на старую схему и отдаёт книгу вложениями.

3. **Настройки параметров:**
   В меню `/settings` (или по кнопке "⚙️ Настройки") доступно управление:
   * **Выбор голоса:** Назначается раздельно для быстрых текстовых сообщений и для длинных книг (нейронные голоса RU/UA/EN/DE/FR/ES/TR, мужские и женские). Полный список — в `keyboards.py`, он сверяется с живым списком edge-tts при старте.
   * **Скорость речи:** Регулировка темпа от -10% до +50%. Настройки сохраняются в локальной БД SQLite индивидуально для каждого пользователя.

## Локальный движок Silero (офлайн)

Кроме облачного edge-tts бот умеет озвучивать локальной нейросетью
[Silero](https://github.com/snakers4/silero-models) — она считает на CPU сервера
и не требует интернета вообще. В меню голосов они помечены "RU офлайн".

Установка (один раз, отдельно от основных зависимостей):

```bash
venv/bin/pip install -r requirements-silero.txt
```

Замеры на i7-6700 (8 потоков, без видеокарты): ~550 символов в секунду,
то есть 100 000 символов — около 3,5 минут, роман на 300 000 — 10-12 минут,
"Война и мир" (~1,2 млн) — порядка 42 минут. Облачный edge-tts в разы быстрее,
но зависит от Microsoft и интернета; Silero — страховка на случай, когда
облако не устраивает.

Особенности реализации, которые важно не сломать:

* модель не переваривает строку длиннее ~1000 символов (падает с
  "probably it's too long"), поэтому для неё чанк 600 символов против 1800 у edge;
* скорость речи у Silero нет в API — она догоняется фильтром `atempo` при
  склейке тома (и при конвертации голосового);
* выдаёт wav 24 кГц, том кодируется в mp3 один раз при сборке;
* модель держится в памяти одним экземпляром, синтез идёт в отдельном потоке,
  чтобы не блокировать event loop бота.

Настройки через переменные окружения: `SILERO_THREADS` (потоки torch, по
умолчанию 4), `SILERO_WORKERS` (параллельных синтезов, по умолчанию 1),
`SILERO_SAMPLE_RATE` (24000), `SILERO_CHUNK_SIZE` (600), `SILERO_WARMUP=1`
(прогреть модель при старте бота), `SILERO_MODEL_ID` (принудительно конкретная
модель).

Обновление движка и модели — `scripts/update_silero.sh`: обновляет пакет
`silero`, список моделей и файл модели, прогоняет живой тест синтеза и
перезапускает бота, а при провале теста откатывает всё из архива в
`/root/telegram/backups`. Скрипт не обращается ни к каким моделям-ассистентам,
это чистый shell. Ставится в cron раз в неделю.

## Обёртка без бота

Тот же движок можно звать из командной строки — `silero_tts_cli.py`:

```bash
venv/bin/python silero_tts_cli.py --voices            # какие голоса доступны
venv/bin/python silero_tts_cli.py --check             # тест модели и замер скорости
venv/bin/python silero_tts_cli.py --text "Привет" -o out
venv/bin/python silero_tts_cli.py --file book.fb2 --voice baya --rate +10%
venv/bin/python silero_tts_cli.py --file book.txt --voice ru-RU-SvetlanaNeural  # облако
```

Короткое имя голоса (aidar, baya, kseniya, eugene, xenia) — локальный движок,
полный код вида `ru-RU-DmitryNeural` — облачный.

## Что стоит в кроне на боевом сервере

* `15 4 * * *` — `scripts/cleanup_books.sh`: удаляет опубликованные книги старше
  `BOOK_TTL_DAYS` дней и пишет в `/var/log/tts-books-cleanup.log`, сколько
  каталогов снесено и сколько места освободилось.
* `30 4 * * 1` — `scripts/update_silero.sh`: обновляет локальный движок Silero
  и файл модели, прогоняет живой тест синтеза, при провале откатывается из
  архива и перезапускает бота (`/var/log/tts-silero-update.log`).
